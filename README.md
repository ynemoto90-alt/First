## 作業手順

### 1. 最新のコードと入力資料を確認する

1. mainの最新状態と、このREADMEを読む。
2. 既存の同名機体・同名画像があるか確認し、追加か差し替えかを区別する。
3. 全長・全幅・ENG中心間・尾翼幅について、数値と根拠を一覧にする。
4. 添付三面図から上面図を特定する。機首を上にし、側面図・正面図・注記を除く。
5. 不足情報が実装を妨げる場合だけ、必要な項目をまとめて確認する。

### 2. 原図の比率を保って画像を作る

- 可能なら元の上面図を直接切り出して加工する。見栄えを整えるための描き直しで寸法比率を崩さない。
- 透過PNGを使い、胴体・主翼・尾翼・ナセル・プロペラ内部の白は残す。
- 胴体とナセルの間など、機体外の空間は透過する。
- 全幅・全長の文字と寸法線は画像内に置く。文字用の外周余白を増やさない。
- 寸法表示を追加した後、最終トリミングと寸法確認をやり直す。
- 透明なごみ画素や寸法線を機体端と誤認しない。アルファの外接矩形だけではなく、実際の翼端・機首・尾部を確認する。
- 機体の線を切り落とさず、余白を最小にする。残った余白はピクセル数と縮尺への影響を報告する。

AIでの生成・編集は、文字入れだけでも形状や余白が変わることがあります。「変更しない」と指示しただけで同一形状と判断せず、結果を測定してください。

### 3. 全体と内部の寸法比率を確認する

画像の横をWpx、縦をHpx、ENG中心間をEpx、水平尾翼幅をTpxとします。最終トリミング後の画像について確認します。

| 確認項目 | 計算 |
|---|---|
| 全体アスペクト比 | Wpx ÷ Hpx と 実全幅 ÷ 実全長 を比較 |
| 表示上のENG中心間 | Epx ÷ Wpx × 設定全幅 |
| 表示上の水平尾翼幅 | Tpx ÷ Wpx × 設定全幅 |
| 余白込み画像での実際の翼端間 | 翼端間px ÷ Wpx × 設定全幅 |
| 余白込み画像での実際の全長 | 機首〜尾端px ÷ Hpx × 設定全長 |

全体の縦横比が一致しても、ENG位置や尾翼幅が正しいとは限りません。比較値・基準値・差を一緒に報告してください。許容誤差が指定されていない場合、独自に「完全一致」「精密」と断定しないでください。

換算：1ft = 0.3048m、1in = 0.0254m。

### 4. HTMLに機体を追加する

`hs_github.html` のボタン群に追加します。

```html
<button onclick="addAircraft('B200')">B200</button>
```

`aircraftSpecs` に同じキーを追加します。寸法単位は **mm** です。

```javascript
B200: {
  length: 13360,
  width: 16610,
  color: '#e74c3c',
  image: 'images/B200.png'
},
```

- length = 全長、width = 全幅。mからmmへの換算を忘れない。
- ボタン・設定キー・画像パスの一致を確認する。
- オブジェクト間のカンマ、括弧、引用符を確認する。
- 既存の画像読み込み・追加・描画・移動・回転処理は、共通処理をそのまま利用する。
- 改行コードなどを不要に変更せず、差分を機体追加に絞る。

### 5. 公開前に確認する

1. JavaScriptが構文エラーなく実行できる。
2. 画像が正しいパスから読み込まれ、代替の色付き矩形にならない。
3. ボタンで機体が追加され、移動・回転できる。
4. 背景が透明で、機体外の格納庫線や他機体が不要に隠れない。
5. 1m目盛りで全幅・全長を確認する。回転後は画面上の縦横と機体の全幅・全長を取り違えない。
6. ENG中心間・水平尾翼幅も確認する。別機種と同寸法の箇所は同じ長さで表示されるか比較する。
7. スクリプト確認だけの場合は、ブラウザで実表示を確認したと報告しない。

### 6. GitHubに反映する

- 最新mainを基準に、画像とHTMLをできれば1つのコミットにまとめる。
- 既存の変更を上書きしない。最新コミットが進んでいた場合は内容を確認して取り込む。
- GitHub側への反映成功を確認し、公開URLを提示する。
- GitHubへの反映とGitHub Pagesへの公開完了は区別する。
- 古い画像が出る場合は公開処理を待ち、PCではCtrl＋F5で再読み込みする。

## 表示が小さいときの切り分け

現行コードは画像全体を次の寸法で描画します。

```javascript
w: spec.width * scale,
h: spec.length * scale
// scale = 0.025（mmからcanvas内部ピクセルへの換算）
ctx.drawImage(img, -ac.w / 2, -ac.h / 2, ac.w, ac.h);
```

画像の余白も設定寸法に含まれるため、余白が大きいほど機体そのものは小さく表示されます。また、widthとheightを個別指定しているため、画像ファイルの縦横比だけを変更しても、描画先の全幅・全長は変わりません。

| 症状 | 確認・対応 |
|---|---|
| 機体全体が小さい | 透明余白、設定寸法、画像読込先を確認 |
| 全幅は合うがENG間・尾翼幅が違う | 画像内部の比率を確認。全体の拡大で直さない |
| 新しい画像に変わらない | mainの画像、公開処理、ブラウザキャッシュを確認 |
| 画像が出ず四角になる | パス・ファイル名の大小文字・読込エラーを確認 |
| 全機体やグリッドが出ない | JavaScript構文エラーを確認 |
| 回転すると横幅が違って見える | 機体の全幅方向と画面の横方向を区別 |

## 今回のB200追加で行ったこと

1. 対象が `hs_github.html`、画像保存先が `images` であることを確認した。
2. 三面図と既存B300画像を参考にB200の上面画像を作成した。
3. 機体外側を透明にし、機体内部の白を残した。
4. `images/B200.png`、B200ボタン、全長13.36m・全幅16.61mの設定を追加した。
5. 格納庫中央に縦横1m単位の目盛りを追加した。
6. ENG中心間と水平尾翼の差を調べ、画像を作り直した。
7. 全幅・全長を画像内に追記した。
8. 最後にユーザーがトリミングした画像を、そのまま `images/B200.png` に差し替えてmainに反映した。

### やり取りが増えた原因と次回の対策

- 最初に画像の見た目を合わせたため、AIによる描き直しでENG位置や尾翼比率が変わった。次回は原図の直接加工を優先する。
- 全体の縦横比だけで修正不要と判断した。次回はENG中心間・水平尾翼幅も最初から検証する。
- 余白の影響を小さいとして扱ったが、画像全体を寸法枠に描く仕様なので余白も表示誤差になる。次回は最後に必ず機体端でトリミングする。
- 透過、寸法表示、トリミング、GitHub反映が別々の依頼になった。次回は冒頭のテンプレートで一括指定する。
- 生成直後の測定値と、後で編集・トリミングした最終画像の測定値は別物。最終ファイルで再確認する。

B200はユーザー判断で完了としています。最終トリミング後のENG中心間・尾翼幅が厳密に実寸一致したと、この記録から断定はできません。次の機体でもB200画像を寸法の原器にはせず、各機体の図面と実寸を基準にしてください。
